DocGuard runs automatically whenever code is pushed. It reads the change, finds the docs it broke, fixes them, and opens a pull request — no human has to remember. Here's exactly how, in 5 steps.

STEP 01 DETECT

Read the change as facts, not text.

DocGuard parses both versions of the code and compares the list of settings — so it sees a rename, not just “some text changed”.

before → after
Query settings (old): …min_length, max_length, regexQuery settings (new): …min_length, max_length, pattern
  • One name removed (regex), one added (pattern) → a rename
  • The old name regex becomes the thing to hunt for in the docs
  • Same logic in Python, TypeScript, JavaScript & Java
STEP 02 MAP · the key idea

How does it know this doc is about Query?

Nothing formally links code and docs. So DocGuard matches the names both sides share. More overlap = stronger match.

code · Query's settings
aliastitlemin_lengthmax_lengthdeprecatedregex → pattern
⇄5 shared names → strong link
doc · the “Recap” section
aliastitlemin_lengthmax_lengthdeprecatedregex
If the names don't match (a rewritten paragraph), it falls back to meaning — and if it's still unsure, it asks a human instead of guessing.
STEP 03 VERIFY

Is it actually wrong — or just related?

A match isn't enough. Not every change breaks a doc. DocGuard checks the one concrete thing that changed.

the check
change:  setting renamed  regex → patternlinked doc still contains “regex” ?  YES → verdict: STALE
  • The old word regex is still literally in the doc → provably out of date
  • If the doc already said pattern → “fine, do nothing”
  • It matches a fact that changed, not a vibe → very few false alarms
STEP 04 REPAIR

Change the one word. Touch nothing else.

after · DocGuard's fix
query-params-str-validations.md · auto

Surgical: only regex becomes pattern. Every other line — headings, order, spacing — stays exactly the same.

To avoid confusion/ 16

It's a proofreader, not an author.

what it does
  • Fixes docs that already exist when code makes them wrong
  • Edits the separate doc files (Markdown pages people read)
  • Changes only the stale words
what it does NOT do
  • Doesn't invent new docs for undocumented code
  • Doesn't edit code comments — the real product docs
  • Doesn't guess when it's unsure — it asks
Fixing an existing sentence is safe. Writing a whole page from scratch would mean the AI guessing — so it doesn't.
