STEP 01 DETECT

Read the diff as facts, not text.

DocGuard doesn't diff strings — it parses both versions of the file and compares structured parameters.

before → after · fastapi/param_functions.py
Query.params (old): [default, alias, title,   min_length, max_length, regex, deprecated]Query.params (new): [default, alias, title,   min_length, max_length, pattern, deprecated]
  • One param removed (regex), one added (pattern), same position →
  • classified as a rename — the change that most often makes docs stale
  • The renamed token regex becomes the thing to hunt for in the docs
This works the same in Python, TypeScript, JavaScript & Java — params are params in every language.
STEP 02 MAP · the core idea

How does it know this doc is about Query?

Nothing formally links them. So DocGuard matches the names both sides share. The more they overlap, the stronger the link.

code · Query() parameters

⇄6 shared names → strong link
doc · “Recap” section symbols

If names don't match (e.g. a rewritten paragraph), DocGuard falls back to meaning — an embedding similarity — and if it's still unsure, it asks a human instead of guessing.
STEP 03 VERIFY

Is it actually stale — or just related?

A link isn't enough. Not every change breaks a doc. DocGuard checks the one concrete thing that changed.

the check
change:  param renamed  regex → patternlinked doc still contains  “regex” ?  YES  →  verdict: STALE  (confidence 0.92)
  • The old name regex is still literally in the doc → provably out of date
  • If the doc had already said pattern → verdict accurate, do nothing
  • No guessing about topics — it matches a fact that changed
This is why false positives are rare: the signal is a specific word that provably moved, not a vibe.
